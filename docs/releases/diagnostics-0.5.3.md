# mindie-diagnostics 0.5.3

更新器使用 `category="update"` 记录失败时，共享记录器按结构化异常事实区分产品错误与环境问题。模块缺失、协议或发行内容异常可进入已授权的上报队列；网络、凭据、权限和本地前置条件问题仍保留本地诊断，不自动创建 Issue。分类不读取异常消息、命令或原始输出。

只读状态为近期错误增加 `error_code` 与 `reporting_eligibility`，区分仅本地记录、记录时未授权、其他配置档案及当前授权状态。`consent_allowed` 仅表示上报资格，实际投递结果以现有队列状态为准。扫描仍限定八个 16 KiB 日志尾部、最多五条近期错误；`truncated` 表示窗口不完整。

本次复用现有去重队列、撤销授权检查和不确定外部写入的对账机制，不回补未授权历史。回归覆盖真实 `python -I` 子进程失败、脱敏投递、重复聚合、环境错误不投递及撤销授权。测试不会向 GitHub 发布测试 Issue。

插件必须同时接入更新失败记录；组件升级本身不能为未记录的旧插件故障补造日志。
