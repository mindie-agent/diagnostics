# mindie-diagnostics 0.5.4

修复冷启动或存在空闲槽位时，本地故障记录可能因读取器元数据协调而被误拒的问题。写入器现在先用 `O_EXCL` 在固定 `BACKUP_COUNT + 1` 个分段槽位内认领从未存在的文件；新文件没有未读字节，因此这条路径不访问读取器注册表，也不打开 SQLite。只有回收已有且归本写入器所有的分段时才进入读取器协调，并继续要求所有登记读取器已消费、遵守背压、原子替换以及如实的 `logging_failed`。

回收路径保留既有的 100ms 协作式工作截止：最多 50ms 等待注册表锁，剩余请求交给 `cursor_snapshot`。该截止只是槽位准入的 best-effort 边界，不是硬延迟上界，也不改变 `cursor_snapshot` 既有的 3.0s SQLite 等待下限；真实回收仍可能超过 100ms。这是已知的 recycle 预算边界，本修复不将其关闭或包装成已解决；超时或游标未知会失败关闭并丢弃记录，不回收未确认消费的数据。

本版本不引入异步采集、常驻 daemon 或 IPC。短生命周期 Hook 仍同步写本地证据；现有 opt-in reporter 仍只扫描已经落盘的日志。异步或队列化采集需要单独设计，不能用退出前无法保证完成的 daemon 线程替代本地写入语义。

回归测试使用真实文件系统、读取器注册表、Outbox/摄取游标和真实跨进程锁，覆盖：注入 101ms 冷启动延迟仍能首次写入；读取器注册表锁被占用时仍能使用空闲轮转槽位；满窗口未读游标继续受到保护；真实背压仍然禁止增长。0.5.3 的读取器保护、原子替换和状态语义保持不变。

包内 `__version__` 同步为 `0.5.4`。
